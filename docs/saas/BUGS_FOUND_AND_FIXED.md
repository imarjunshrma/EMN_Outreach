# Bugs found and fixed — v1.3 product audit

Every fix below has a test that fails without the fix (or, for build and dependency items, a recorded check). Severity: **High** = security, data loss or wrong outreach behaviour; **Medium** = wrong result or error a user would hit; **Low** = code quality with no user impact.

| # | Severity | Area | What was wrong | How it was found | Fix | Proof |
|---|---|---|---|---|---|---|
| 1 | High | Mailboxes / security | The Google/Microsoft OAuth callback trusted the `state` value alone. A consent link started by one person could be completed by another signed-in person, attaching the second person's mailbox to the first person's workspace (OAuth login CSRF). | Code review of the callback | The callback now requires the signed-in user to be the user who started the connection and to still have access to the workspace | `mailboxes.test.ts` › "a consent link started by someone else…" |
| 2 | High | Compliance | A disposable-domain verification record was stored without an expiry, so the send-time check ignored it. With "unknown results: allow", a disposable address could be emailed. | Failing test after the user's verification rework | Record stored with the workspace freshness window | `domains-enrichment.test.ts` |
| 3 | High | Email verification | Processing a CSV row replaced its stored details and dropped the uploaded row. Exports lost the customer's own columns and every result column shifted left under the wrong header. The retry and failure paths had the same overwrite. | New end-to-end CSV test | Uploaded row kept on the complete, retrying, failed and manual-retry paths | `email-verification-flow.test.ts` (export alignment, retry keeps row) |
| 4 | High | Database | Migration `20261121193000` was edited after it had been applied, so existing databases lacked `hasHeader` and six other batch columns while fresh ones had them. | 31 failing tests on an existing test database | Idempotent repair migration `20261122110000_email_verification_batch_repair`; nothing deleted or rewritten | Existing and fresh databases compared equal |
| 5 | Medium | API | Any route given a malformed record ID (`/leads/abc`) answered 500, because the database rejected the value. Affected every one of the ~300 routes with an `:id`-style parameter. | Security baseline probe | Router answers 404 for malformed UUID parameters, after authentication and access checks | `security-baseline.test.ts` |
| 6 | Medium | Email verification | Exporting another workspace's batch answered 500 instead of 404 (no data leaked). | Isolation test | `NotFound` error | `email-verification-flow.test.ts` |
| 7 | Medium | Email verification | Duplicate addresses within one CSV kept the last occurrence rather than the first. | Export test | First occurrence kept | `email-verification-flow.test.ts` |
| 8 | Medium | Platform admin | Per-tenant module and limit switches had no effect while billing is off (self-hosted), because entitlements ignored overrides in that mode. Copilot, workflows, auto-reply, waterfall and API access could not be switched off per tenant. | Console tests | Admin overrides stored on the organization (tenants cannot write them) and applied in both modes; the four features that skipped checks when billing was off now honour them | `platform-admin.test.ts` |
| 9 | Medium | Dependencies | `npm audit --omit=dev`: 3 high (Prisma CLI pulled `effect` 3.20.0) and 1 high + 1 moderate (Next.js bundled `postcss` 8.4.31). | `npm audit` | npm `overrides`: `effect` 3.22.5, `postcss` 8.5.33 — same major versions | 0 vulnerabilities; Prisma validate/generate and full Next build pass |
| 10 | Low | Email verification | One unused database query per verification; unused variables; a control-character regular expression (4 lint errors). | `eslint` | Removed; replaced with `isAsciiLocalPart` | 0 lint errors |
| 11 | Low | Tests | 30 tests used a stale helper (VALID lead without a verification date), failing against the stricter freshness rule. | Full run | Helper sets `emailVerifiedAt` | Suites pass |
| 12 | Low | Tests | Database reset between tests could deadlock with a leftover background write. | Intermittent failure in a coverage run | Reset retries only on Postgres deadlock code `40P01` | Full run passes |
| 13 | Low | Tests | A browser assertion was ambiguous when two identical toasts were visible. | e2e run | Targets the newest toast | 18/18 e2e |

Not counted as bugs: a waterfall test expected disposable domains to return "invalid", but the owner had deliberately changed them to "unknown"; the test was updated to the new rule and that change led to bug 2.
