## Migration and persistence status

`prisma migrate deploy` is used by deploy and Compose migration flows; `scripts/apply-sql.ts` runs idempotent supplemental SQL. FK, unique and index definitions are in schema and generated migration SQL. Prisma schema validation passed in this environment. Fresh migrations and supplemental SQL were applied to new local databases in a temporary PostgreSQL cluster; the full integration suite exercised database CRUD/constraints. The Compose migration path was smoke-tested with distinct non-superuser owner and runtime roles; the app role could SELECT and was denied DDL. Docker migration ordering/volumes, production upgrade, backup/restore and persistence across container restart remain unverified. No existing database/volume was changed and migration history was not rewritten. No RLS clauses or separate Tenant model are present.
