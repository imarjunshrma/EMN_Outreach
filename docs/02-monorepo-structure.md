# 02 — Repository structure

Single npm package at the root (backend + worker + shared + integrations + scripts + tests) and a separate
npm package in `frontend/`. ESM everywhere (`"type": "module"`), TypeScript `NodeNext` with `.js` import suffixes.

```
emn-outreach-os/
├─ backend/src/
│  ├─ core/        config (zod env), logger (pino + redaction), db (Prisma client factory), crypto (AES-GCM keyring, HMAC, PKCE),
│  │               errors, storage (LocalDiskStorage), redis (locks, rate limits), queues, audit/publish, container (adapter DI)
│  ├─ http/        router (route registry), middleware (auth, CSRF, headers, errors), openapi builder
│  ├─ services/    auth, workspace, leads, intelligence, ai, accounts, engine, inbox, crm, automation, webhooks,
│  │               compliance, integrations, analytics, ops
│  ├─ routes/      core, leads, intelligence, outreach (route definitions only)
│  ├─ generated/   Prisma client (generated by `prisma generate`, not committed / not zipped)
│  ├─ app.ts       Express app (public endpoints, SSE, registry mounting)
│  └─ main.ts      listen on 127.0.0.1:API_PORT, graceful shutdown
├─ worker/src/     processors.ts (handlers per queue), main.ts (workers + schedules)
├─ integrations/src/
│  ├─ ai/          anthropic, openai, guard (untrusted wrapping, quote checks), types
│  ├─ email/       gmail, microsoft, smtp-imap, mime (build/parse, DSN, auto-reply), types
│  ├─ providers/   Apollo, MillionVerifier, Brave, Serper, Smartlead
│  ├─ research/    SafeFetcher (SSRF/robots), dns checks
│  └─ http.ts      fetch wrapper with retries / Retry-After / ProviderError
├─ shared/src/     template, schedule, compliance, permissions, ai-schemas, prompts
├─ prisma/         schema.prisma, migrations/, sql/001_indexes_and_guards.sql, seed.ts
├─ frontend/       app/ (routes), components/, lib/ (api client, hooks, format)
├─ tests/          unit/, integration/, helpers/ (fakes, harness, global setup)
├─ deployment/     nginx, systemd, pm2, logrotate, postgres, redis
├─ scripts/        install/deploy/backup/restore/healthcheck (bash), apply-sql, create-admin, reset-password, gen-keys, generate-openapi, generate-api-docs
└─ docs/
```

Rules enforced by ESLint/tsconfig: server code never imports the frontend; the frontend only talks to the API over HTTP
(Next rewrites `/api/*` to the API in dev; Nginx routes it in production). `shared/` has no Node-only or DB imports.

Build outputs: `dist/` (tsc, backend/worker/shared/integrations) and `frontend/.next`. Neither is committed or zipped.
